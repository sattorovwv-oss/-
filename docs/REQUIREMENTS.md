# Tuman Kargo — актуальные требования

Это рабочая спецификация по исходному DOCX и уточнениям заказчика. Исходный документ описывает один склад; здесь он расширен двумя складами и личным кабинетом на сайте.

## Согласованные изменения

- Одна система, один Telegram-бот, общая база. Два склада: Китай и Таджикистан.
- Отдельные доступы складов; роль определяется сервером. Обычная регистрация создаёт только клиента.
- Клиентский сайт: регистрация, вход, свои посылки, поиск, обращения, привязка Telegram.
- Сотрудники: свой интерфейс склада, сканы, вес, цена, оплата, разрешённые изменения статуса, подтверждение владельца, ответы поддержки, Excel.
- Владелец: оба склада, тариф и валюта, рассылки, архивирование, очередь уведомлений.
- Изменение своего логина/пароля, список активных сеансов, завершение других/отдельных сеансов. Изменение реквизитов завершает остальные сеансы и отзывает неиспользованные ссылки входа.
- Администратор открывает сайт кнопкой в боте без повторного пароля. Требуется заранее назначенный Telegram ID; ссылка одноразовая, на две минуты. Telegram-бот не выдаёт роль по публичной регистрации или текстовому паролю в переписке.
- Бот клиентов: русский/таджикский. Сайт и функции сотрудников: преимущественно таджикский, пояснения по безопасности также на русском. Переводы требует вычитать носителю языка перед приёмкой.
- Цвета: красный danger для отмены/опасных действий и фирменных акцентов, зелёный success для подтверждения, primary для переходов. Отображение стилей Telegram зависит от версии приложения клиента.

## Маршрут и полномочия

`Ожидается → Склад Китай → Отправлена из Китая → Склад Таджикистан → Выдана`

- Приём на склад производится сканированием; Китай может поставить статус «Отправлена», Таджикистан — «Выдана» после своего приёма.
- Таджикистан может принять посылку, даже если Китай пропустил скан.
- Повторный скан не создаёт вторую посылку и второе событие о том же приёме. Старый склад не может понизить статус.
- В клиентском поиске и списке показывается текущий статус. Старая переписка Telegram не удаляется. Внутренняя история сохраняется.
- Неотправленные уведомления о более раннем складе подавляются после перехода посылки дальше по маршруту.

## Сканеры и сбои

Поддерживаются USB/Bluetooth-сканеры в режиме эмуляции клавиатуры с суффиксом Enter. Сканер должен физически уметь читать тип штрихкода на этикетке. COM/RS-232, SDK конкретного производителя, скан с камеры и весы требуют отдельного согласования/интеграции. Сканер передаёт код, но не вес.

Трек: 6–40 латинских букв, цифр и дефисов; пробельные символы удаляются, регистр верхний. Если реальный перевозчик использует другой формат, нужно предоставить образцы до рабочего запуска.

Очередь страницы сохраняется в IndexedDB отдельно по аккаунту и складу. Отправка последовательная, у каждого скана постоянный UUID. Сервер атомарно сохраняет приём и уведомление. При потере ответа повтор того же UUID возвращает сохранённый результат. Ошибочные коды остаются на экране до решения сотрудника.

До подтверждения сервера скан считается ожидающим, а не принятым. Закрытие браузера/очистка его хранилища до синхронизации может уничтожить локальную очередь; полную неуязвимость к этому обещать нельзя. Без интернета сайт при первом открытии не загружается; это не автономное приложение.

## Владение и выдача

Предложенное защитное дополнение: добавленный клиентом трек создаёт заявку. Сотрудник проверяет принадлежность по данным реального заказа и подтверждает владельца. Без этого доступны лишь код и общий статус, без имени другого клиента, веса и цены. Формат доказательства (номер заказа, клиентский код перевозчика, документ) владелец склада должен определить перед рабочей приёмкой.

Один трек не является разрешением на физическую выдачу товара. Сотрудник проверяет получателя по правилам склада, затем ставит «Выдана». Автоматической интеграции с перевозчиками или документами нет.

## Уведомления и хранение

Все валидные сканы сохраняются независимо от наличия Telegram у клиента. Сообщение отправляется, когда владелец подтверждён, Telegram привязан и пользователь запускал бота. Клиент без Telegram пользуется сайтом.

Очередь отправки хранится в SQLite и переживает перезапуск. Временные ошибки повторяются с задержкой; запрет Telegram отображается как blocked. Статус sent означает принятие сообщения Telegram API, не прочтение человеком. На неоднозначном сетевом таймауте возможен повтор сообщения: Telegram не предоставляет ключ идемпотентности sendMessage.

Цель до 5 секунд применима при доступных сервере/сети/Telegram и отсутствии ограничения частоты. Это не гарантия при внешних сбоях.

SQLite WAL на постоянном диске; один экземпляр приложения. Резервные копии через SQLite Backup API каждые 6 часов, 28 последних, с проверкой целостности. Внешняя копия на другом носителе обязательна для защиты от потери сервера, но её место ещё не задано. Автоматического разрушительного «ремонта» повреждённой базы нет.

## До приёмки

Нужно предоставить действующий токен бота через защищённые настройки, Telegram ID сотрудников, домен и сервер. Настроить DNS/HTTPS, первоначальные доступы, внешние бэкапы; проверить реальные этикетки и сканеры на обоих складах, уведомления и вход через установленное приложение Telegram. Пройти контроль выдачи и вычитку таджикских текстов. Локальные тесты не заменяют эти проверки.
