Автотесты включают параллельные сканы и повторы UUID, движение между складами без регрессии, проверку владельца, изоляцию прав, округление денег, Excel без формул, восстановление из бэкапа, одноразовые/просроченные ссылки, смену реквизитов и отзыв сеансов. Telegram dispatcher проверяется записывающим транспортом; очередь — успешной отправкой, временным отказом, rate limit, блокировкой клиента и подавлением устаревшего уведомления о Китае.

Браузерные сценарии:

1. Двенадцать быстрых вводов сканера, по одной записи на код.
2. Отключение связи, сохранение очереди при перезагрузке и последующая отправка.
3. Регистрация клиента, заявка на привязку, подтверждение сотрудником.
4. Приём в Таджикистане, новый статус клиента, запрет возврата в Китай старым сканом.
5. Явное подтверждение привязки Telegram с сохранением посылок.
6. Вход администратора по одноразовой ссылке без пароля.
7. Завершение другого сеанса администратором.
8. Отображение desktop-панели и мобильного клиентского кабинета без переполнения страницы.

В тестовом транспорте Starlette выдаёт предупреждение о будущем переходе с httpx на httpx2; проверки завершены успешно. Реальные ключи и персональные данные при проверках не использовались. Браузерные тесты создают отдельную временную базу и останавливают свой сервер.

**Ещё не проверено:** действующий Telegram-бот и его реальные цветные кнопки/уведомления, реальные USB/Bluetooth-сканеры и штрихкоды, домен/DNS/сертификат на VPS, доставка между сетями складов, внешние резервные копии и полный приёмочный прогон. Требуются реальные ресурсы и доступы по списку в DEPLOYMENT.md. CI настроен в репозитории, его выполнение на GitHub подтверждается отдельно.

Google-тесты проверяют CSRF, PKCE, одноразовый state, привязку к браузеру,
истечение срока, отмену, повтор callback, отказ провайдера, отзыв сеанса во
время обмена, запрет служебных ролей, явную привязку с сохранением Telegram
и посылок, отсутствие объединения по email, первый локальный пароль только
после свежего Google-входа и безопасное обновление .env. Отдельно проверены
фиксированные HTTPS endpoints, отсутствие редиректов с секретами и отклонение
некорректных ответов провайдера.

Браузер проходит настоящий маршрут сайта, включая переход на другой origin
и возвращение с cookie. Страница Google и ответ UserInfo имитируются в
изолированном тестовом приложении. Реальный Client Secret не использовался.
Проверка с настоящим Google-аккаунтом остаётся после настройки Google Cloud
и обновления VPS; это обновление ещё не подтверждает работу Google на VPS.
Изменение схемы не удаляет старые данные, однако перед рабочим обновлением
нужна штатная резервная копия. GitHub CI для текущего коммита проверяется отдельно.
