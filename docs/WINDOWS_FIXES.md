# Исправления по первому запуску на Windows

В логе пользователя подтверждены три разные причины. Рабочие данные не требуют удаления или миграции.

## Даты и Excel

Windows не предоставляет IANA timezone database, поэтому `ZoneInfo("Asia/Dushanbe")` вызывал исключения при отображении дат. По ТЗ часовой пояс фиксирован: UTC+5, без настройки и переключения DST. Для дат сайта и Excel теперь используется встроенный `datetime.timezone` с этим смещением. Дополнительный пакет `tzdata` не требуется.

Регрессионная проверка отключает системные timezone paths и импорт tzdata, подтверждает отсутствие IANA-зоны и выполняет реальные запросы к клиентскому кабинету с посылкой/обращением и к Excel. Даты сохраняют смещение +05:00.

## Локальный адрес сайта

Telegram отклонил inline-кнопку с локальным URL. В локальном режиме бот больше не создаёт такую кнопку и не выпускает неиспользуемый токен входа; показывает пояснение о публикации сайта. Статистика, тариф и рассылки администратора остаются доступны через callback-кнопки. Для перехода на сайт нужен корректный публичный HTTPS-origin в PUBLIC_URL. Проверка пригодности URL не доказывает его сетевую доступность.

## Обрыв Telegram-соединения

`WinError 64` означает обрыв сетевого соединения; лог не устанавливает точную причину в Windows/сети. Отдельные поддерживаемые API-запросы теперь повторяются не более двух раз после первой попытки. Обработчик бизнес-операции заново не выполняется. Постоянный отказ остаётся видимым: при обработке сообщения сохраняется уведомление о восстановлении в outbox, а при невозможности первоначального подключения программа завершается с ненулевым кодом и понятным сообщением.

Ошибки API, не связанные с транспортом, не повторяются этим механизмом. Polling сохраняет собственный backoff aiogram. TLS-проверка остаётся включённой. В лог повторов не включаются полные URL/тексты исключений, способные содержать секреты. Возможен дублирующий ответ при неоднозначном сетевом сбое, поскольку sendMessage не поддерживает ключ идемпотентности.

## Пакет для существующей установки

`scripts/build_windows_fix.py` формирует один файл `update_tuman.py` с семью проверяемыми исходными файлами внутри. Его запускают тем же Python после остановки бота. До замены проверяются контрольные суммы и синтаксис; старый код сохраняется в `var/code-backups/`. Если проверка импорта не проходит, заменённые файлы откатываются. `.env`, существующая база и зависимости не изменяются. Применение и откат проверены отдельными тестами.

## Границы проверки

Локальные тесты воспроизводят отсутствие timezone database, запрещённые локальные Telegram-кнопки, сетевой сбой после выбора языка, восстановление запроса, постоянный отказ с сохранением посылки и уведомлением из очереди. Настроен CI на Ubuntu и Windows. Выполнение Windows CI, фактическая сеть пользователя и реальная доставка Telegram подтверждаются отдельно; Linux-тесты не следует выдавать за запуск на Windows.
