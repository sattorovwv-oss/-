# Tuman Kargo

Telegram-бот, два склада (Китай/Таджикистан), веб-панель и личный кабинет клиента. Python 3.12, aiogram, FastAPI, SQLite WAL, HTML/CSS/JS. Одна база и один работающий процесс.

Актуальные требования и ограничения: [docs/REQUIREMENTS.md](docs/REQUIREMENTS.md). Развёртывание и приёмка: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Локальный запуск

Используйте существующий checkout. Облачная задача уже изолирована; отдельный Git worktree не нужен.

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.lock
cp .env.example .env
```

На Windows: `py -3.12 -m venv .venv`, далее `.venv\Scripts\python.exe`. `.env` редактируется локально; токены и рабочие пароли нельзя коммитить. Все относительные пути к БД считаются от проекта.

Создайте учётные записи с собственными паролями. CLI спрашивает пароль скрыто; встроенных паролей нет:

```sh
.venv/bin/python -m tuman.cli create-admin --role owner --login owner
.venv/bin/python -m tuman.cli create-admin --role china --login china
.venv/bin/python -m tuman.cli create-admin --role tajik --login tajik
```

Для настоящего бота заполните `BOT_TOKEN` и `PUBLIC_URL`. Владелец/сотрудники получают свой ID командой `/id`; назначьте их через CLI или соответствующие `*_TELEGRAM_IDS`:

```sh
.venv/bin/python -m tuman.cli bind-telegram --login china --id YOUR_NUMERIC_ID
.venv/bin/python main.py
```

`/panel` выдаёт администратору персональную кнопку входа. Клиент регистрируется на сайте, входит, затем открывает ссылку `/website` из своего диалога с ботом и подтверждает привязку. После привязки `/website` сразу открывает кабинет. Не пересылайте ссылки: в пределах двух минут это секреты доступа.

Для разработки сайта без токена явно задайте `WEB_ONLY=1` в локальном `.env`. Уведомления останутся в базе до запуска настоящего бота; на страницах показывается предупреждение. Production запрещает этот режим. Запуск по умолчанию останавливается без токена/аккаунта владельца. На Windows после настройки доступен `start.bat`.

## Проверки

```sh
.venv/bin/python -m pytest -q
.venv/bin/python -m playwright install chromium
.venv/bin/python -m tests.browser_flow
```

Браузерный тест использует временную базу, тестовые учётные записи и локальный процесс. В Linux можно использовать системный Chromium; путь переопределяется `CHROMIUM_PATH`. Результаты и снимки: `test-results/`, не коммитятся. Тесты Telegram используют записывающий транспорт и не обращаются к реальному боту.

## Возможности

- Раздельные серверные права складов, приём с клавиатурного сканера, устойчивость к повторам/параллельным запросам, запрет понижения статуса.
- Клиентская регистрация, поиск, подтверждение принадлежности, свои посылки, поддержка, привязка Telegram.
- Два языка бота, калькулятор, личный кабинет, админ-панель, статистика, ответы поддержки и рассылки.
- Вес, стоимость, отметка оплаты, история операций, Excel с защитой от формул, архивирование вместо потери истории.
- Одноразовые ссылки, хешированные пароли scrypt, HttpOnly-сеансы, CSRF, ограничения попыток входа, завершение сеансов и изменение реквизитов.
- Постоянная очередь уведомлений, обработка блокировки/ограничений Telegram, подавление старых уведомлений о складах.
- Бэкапы каждые 6 часов, проверка целостности, контроль единственного процесса.

Сайт на GitHub Pages не запускается: ему нужны Python-сервер, постоянный диск и работающий бот. GitHub хранит код и запускает CI; VPS с HTTPS обслуживает сайт. Токен бота, живую базу и `.env` в GitHub не загружайте.
